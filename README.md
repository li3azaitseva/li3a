# Елизавета Зайцева — портфолио

Статический одностраничный сайт. Без сборки, без Node.js, без фреймворков.
Только HTML, CSS и ванильный JavaScript.

```
/
├── index.html          разметка страницы
├── styles.css          все стили (палитра — в самом верху файла)
├── script.js           поведение + ДАННЫЕ КЕЙСОВ
├── _headers            заголовки кеширования для Cloudflare Pages
├── assets/
│   ├── clouds/         8 нарисованных облаков (.svg, ~32 КБ всего)
│   ├── images/         портрет, аватар в шапке, логотип
│   ├── projects/       изображения работ
│   ├── img/            исходники до оптимизации (в продакшн не нужны)
│   └── raw/            оригиналы с диска (в продакшн не нужны)
└── _backup_prev/       предыдущая версия сайта
```

---

## Как открыть локально

Двойным кликом по `index.html` — сайт полностью работает по протоколу `file://`,
локальный сервер не требуется.

Если всё-таки нужен сервер (например, чтобы проверить заголовки):

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000`.

## Публикация

### Почему Workers, а не Pages

В репозитории лежит `wrangler.jsonc` для **Cloudflare Workers Static Assets**,
а не для Pages. Причина простая: ключи `workers_dev` и `preview_urls`, которые
отключают служебные адреса, существуют только у Workers. У Pages служебный
адрес вида `li3a.pages.dev` конфигом не отключается вовсе — он часть продукта,
и убрать его нельзя ни через `wrangler.toml`, ни через панель.

Для этого сайта Workers подходят полностью: `_headers` они читают так же,
шага сборки нет, статика отдаётся с той же сети.

### Как выложить

```bash
npx wrangler deploy
```

Первый запуск попросит войти в Cloudflare через браузер. Дальше — то же самое
при каждом обновлении. Если хотите, чтобы деплой шёл сам после `git push`,
подключите GitHub Actions с `cloudflare/wrangler-action`.

### Что уезжает на хостинг

Список исключений — в `.assetsignore` рядом с конфигом. Wrangler читает
именно его, а **не** `.gitignore`: без этого файла на Cloudflare уехали бы
`assets/img` и `assets/raw` — около 140 МБ мастер-файлов, включая исходники
клиентских макетов. Сейчас выгружается 95 файлов, 7,6 МБ.

### Домен

`li3a.ru` и `www.li3a.ru` привязаны прямо в конфиге, в секции `routes`.
Запись в DNS Cloudflare создаёт сам — заводить её отдельно не нужно,
достаточно, чтобы зона уже была в вашей учётной записи.

`www` здесь не для красоты. Пока такой записи не было, DNS на запрос
`www.li3a.ru` отвечал «домена нет», и у всех, кто набирал адрес с `www` или
переходил по старой ссылке, сайт не открывался вообще. В отличие от
распространения DNS у нового домена, само это не проходит — нужна запись.
Сертификат выписан на `li3a.ru` и `*.li3a.ru`, поэтому со стороны шифрования
поддомен готов.

Осталось одно ручное действие в панели Cloudflare: правило перенаправления
`www.li3a.ru` → `li3a.ru` (Rules → Redirect Rules). Без него получится два
разных адреса с одинаковым содержимым, и поисковик сам решит, какой считать
главным, — а в `<head>` и в JSON-LD у нас везде прописан голый `li3a.ru`.

Там же стоит включить **SSL/TLS → Edge Certificates → Always Use HTTPS**:
сейчас `http://li3a.ru` отдаёт страницу с кодом 200, а не перенаправляет
на https.

### Если всё же захотите Pages

Ниже — прежняя инструкция. Работать будет, но `li3a.pages.dev` останется
доступным вдобавок к вашему домену.

## Как опубликовать на Cloudflare Pages

**Вариант 1 — загрузка папкой (без Git):**

1. Dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
2. Загрузите `index.html`, `styles.css`, `script.js`, `_headers`, `robots.txt`,
   `favicon.ico`, `site.webmanifest` и папки `assets/clouds/`, `assets/images/`,
   `assets/gallery/`, `assets/projects/`.
3. **Build command** и **Output directory** оставьте пустыми — это чистая статика.

**Вариант 2 — из репозитория:**

1. Залейте проект в Git-репозиторий.
2. Pages → **Connect to Git** → выберите репозиторий.
3. Framework preset: **None**. Build command: пусто. Output directory: `/`.

> **Важно при загрузке папкой.** Не перетаскивайте на Cloudflare весь каталог
> проекта целиком: внутри лежат `assets/img/` (49 МБ) и `assets/raw/` (92 МБ) —
> ваши мастер-файлы и исходники клиентских макетов. Сайт на них не ссылается,
> но после загрузки они окажутся в открытом доступе: любой, кто угадает путь,
> сможет их скачать. Загружайте только перечисленные выше файлы и папки, либо
> заранее перенесите `img/` и `raw/` из каталога проекта куда-нибудь рядом.
> При публикации из Git это уже учтено — обе папки в `.gitignore`.

### Домен

Сайт рассчитан на **https://li3a.ru** — адрес уже прописан. Он встречается
в пяти местах:

| Где | Что |
|---|---|
| `index.html`, блок «АДРЕС САЙТА» | `canonical`, `og:url`, `og:image` |
| `index.html`, JSON-LD в конце `<head>` | `url` и `image` |
| `robots.txt` | закомментированная строка `Sitemap` — на будущее |

Абсолютные адреса нужны именно соцсетям и поисковику: относительные они
не разворачивают, и превью ссылки в Telegram, VK или LinkedIn не собирается.

**Чего домена намеренно нет** — в `site.webmanifest`: там `start_url` и `scope`
относительные. С абсолютными манифест действителен только на самом li3a.ru,
а на превью-домене Cloudflare (`*.pages.dev`) и при открытии `index.html`
с диска браузер его отверг бы.

**Если домен сменится:** правите три строки в блоке «АДРЕС САЙТА», два поля
в JSON-LD, строку в `robots.txt` — и обязательно пересчитываете хеш CSP
в `_headers` (JSON-LD изменился, старый хеш перестанет совпадать). Команда
для пересчёта — в разделе про заголовки безопасности.

## Где что менять

### Тексты

Заголовок первого экрана — один `<h1>` из трёх строк: род занятий
(`.hero__title-role`, мельче и с разрядкой) и две строки имени. Вместе они
читаются как одна фраза «Графический дизайнер Елизавета Зайцева», при этом имя
остаётся главным по масштабу. Отдельной надстрочной строки над заголовком
больше нет — она переехала внутрь.

Все тексты — прямо в `index.html`, на русском, разделены комментариями по секциям
(`A. ШАПКА`, `B. HERO`, `D. ИЗБРАННЫЕ РАБОТЫ` и т. д.).

**Исключение:** развёрнутые описания кейсов, которые открываются в модальном окне,
лежат в `script.js` в объекте `PROJECTS` (раздел `01. ДАННЫЕ КЕЙСОВ`, самое начало файла).

### Цветовая палитра

`styles.css`, самый верх файла, блок `:root` (раздел `01. ТОКЕНЫ`):

```css
--ink:        #151D3C;   /* основной текст */
--accent:     #1B3AA8;   /* глубокий ультрамарин */
--accent-ink: #16286F;   /* акцент для мелкого текста и ссылок */
--sky-deep:   #4775E1;   /* глубина неба, декоративные акценты */
--sky:        #5FA3F0;   /* небо */
--sky-light:  #8CBFF6;   /* светлое небо */
--muted:      #6E80A6;   /* линии, рамки */
--muted-ink:  #232E50;   /* мелкий приглушённый текст */
--paper:      #F2F0ED;   /* «бумага» — с фона ваших обложек */
```

**Почему цвета перестали спорить.** Я снял пипеткой ваши собственные цвета
с обложек кейсов: синяя плашка `#2437AB`, чернила рисунков `#1C56DE…#2335A8`,
бумага `#ECEAE6`. Все ваши синие лежат в тоне **222–232°**. Прежняя палитра
сайта была голубой с тоном ~200°, а декор — на 247°: разрыв в 47° и создавал
ощущение несобранности.

Теперь **вся палитра уложена в диапазон 212–228°** — одно семейство тона,
поэтому любые два цвета сочетаются по определению. Опорная точка — ваш
ультрамарин. «Бумага» намеренно тёплая (36°): это единственный контрапункт,
и он взят с фона ваших же обложек, так что карточки на сайте и ваши работы
сделаны из одного материала.

Градиент фона задан отдельно, в `body::before`, в том же диапазоне.

**Про пару «обычный / -ink».** Градиент привязан к экрану, а не к документу,
поэтому любой текст при прокрутке проходит через самый насыщенный стоп (`#5FA3F0`). На нём `--accent` даёт 2,4:1 — ниже порога. Поэтому:

* `--accent` и `--muted` — заливки, линии, крупные начертания;
* `--accent-ink` (5,1:1) и `--muted-ink` (5,1:1) — весь мелкий текст и ссылки.

Сохраняйте это разделение при правках. Контраст всех текстовых элементов
проверен: нарушений нет.

Главная кнопка (`.btn--accent`) сделана заливкой, а не контуром: акцентный текст
на насыщенном небе давал около 3:1, заливка даёт 5,0:1 и заодно делает CTA заметнее.

Общий градиент фона страницы задан отдельно, в `body::before`.

### Логотип в шапке

`assets/images/logo-li3a.png` (319×94) — знак Li3a слева в шапке. Раньше там
стояли круглое фото и имя в две строки.

Знак **перекрашен в `--ink`**, хотя ваш исходник белый. Причина в том, что
шапка живёт в трёх состояниях: прозрачная поверх неба, молочная при скролле
(`.is-stuck`) и поверх раскрытого мобильного меню на бумажном фоне. Белый знак
читался бы только в первом, в двух других исчезал бы совсем. Чернильный
работает во всех трёх: 6,3:1 на небе и ещё выше на молочном.

Белый оригинал никуда не делся — он лежит в `assets/img/my_logo.png`.
Пересобрать чернильную версию из него можно так (из папки проекта; нужен
Pillow — если его нет, сначала `pip3 install pillow`):

```bash
python3 -c "from PIL import Image; im=Image.open('assets/img/my_logo.png').convert('RGBA'); im=im.crop(im.getchannel('A').getbbox()); o=Image.new('RGBA',im.size,(0x15,0x1D,0x3C,0)); o.putalpha(im.getchannel('A')); o.save('assets/images/logo-li3a.png',optimize=True)"
```

Высота задаётся в `.brand__logo` (`clamp(24px, 2.3vw, 32px)`) — именно высота,
а не ширина: знак горизонтальный, пропорция 3,39, и по высоте он должен
совпадать с ритмом шапки.

`alt` у картинки пустой намеренно: имя ссылки задано в `aria-label`, иначе
скринридер прочитал бы «Li3a» дважды.

Вместе с фото из шапки удалены два файла, на которые больше никто не ссылается:
`assets/images/avatar.jpg` и `assets/images/logo-lz.png` (копия белого знака).

Логотипа VOIS в папке на Диске не было — я вырезал его с вашего собственного

В исходнике «Старлекс» контрформы букв «А» и «Р» залиты **белым**, а не прозрачны
(логотип рисовался под красную плашку). Поэтому непрозрачность считается как
`alpha × (1 − светлота)`: чёрный штрих остаётся, белые контрформы выбиваются
насквозь и сквозь них видно фон.

**Про размер.** Ряд выровнен не по одной высоте, а оптически: у каждого знака
свой коэффициент `--logo-k` в разметке. Однострочные логотипы (VOIS, STIHL)
идут в базовом размере, составные — в две строки или со стопкой (Старлекс,
ЦНИИМФ, Самолёт Плюс, MPSELLERS, SporeLab) — крупнее. При жёстком ограничении
по высоте узкие и многострочные знаки читались заметно мельче остальных.

Ряд — не сетка, а `flex` с переносом: в сетке широкие знаки упирались в ширину
колонки и сжимались по ширине, из-за чего выходили ниже заданной высоты. Во flex
каждый логотип занимает свою натуральную ширину. Количество брендов можно
менять, не трогая CSS.

Чтобы добавить компанию: положите PNG или SVG в `assets/images/logos/`
и добавьте `<li class="client">` в секцию `H. СОТРУДНИЧЕСТВО` в `index.html`,
задав `--logo-k` под пропорцию знака.

### Иконки инструментов

`assets/images/tools/` — Photoshop, Illustrator, InDesign, Figma, After Effects.
Взяты из набора [Simple Icons](https://simpleicons.org): сами контуры
опубликованы под **CC0**, поэтому их можно свободно использовать. Товарные знаки
при этом остаются собственностью Adobe и Figma — иконки уместны как обозначение
софта, которым вы работаете, но не как элемент вашего бренда.

В разметке они вставлены инлайном (одним `<path>` каждая), чтобы перекрашиваться
в цвет сайта через `fill`. Файлы `.svg` в папке — исходники: если понадобится
заменить или добавить инструмент, возьмите иконку оттуда же и вставьте её `<path>`
в блок `.tools` в `index.html`.

## Облака

Облака нарисованы, а не сфотографированы: SVG в стиле детского рисунка,
**белые**, с рыхлой заливкой — как будто раскрашивали карандашом и не
попадали в границы.

Заливка складывается из трёх слоёв: лёгкая подложка (16% непрозрачности),
волнистая штриховка внутри контура с разным нажимом и просветами, и один
ход, который намеренно вылезает за контур. Плотной заливки нет — сквозь
облако видно небо.

**Фон пришлось углубить.** Прежняя середина градиента была почти белой
(`#DFEDFB`), и белая линия на ней просто исчезала. Сейчас диапазон
`#5FA3F0…#8CBFF6`: белое читается везде (2,6:1 на тёмном стопе), а текст
остаётся в норме — самый тёмный стоп задаёт худший случай, и все токены
под него пересчитаны.

**Три манеры рисования**, чтобы облака не повторяли друг друга:

* `double` — контур обведён дважды со смещением, как будто ребёнок обвёл ещё раз;
* `single` — одна уверенная линия;
* `spray` — контур плюс россыпь точек по кромке, эффект баллончика.

Форма каждого облака собирается из долей со случайным радиусом (3–6 долей),
одна доля всегда заметно выше остальных — это убирает симметрию. Дальше
контур проходит через двухступенчатый SVG-фильтр: низкочастотная
турбулентность даёт кривизну руки, высокочастотная — зерно бумаги.
Всего 12 файлов в `assets/clouds/` (`c1…c12.svg`), примерно по 1–3,6 КБ.

**Два слоя.**

* **Заднее небо** (`#sky`, `z-index: -1`) — 14 облаков с параллаксом.
  У каждого своя стартовая высота и длина пути (`data-start` / `data-travel`
  в разметке, в `vh`), поэтому в кадре почти всегда несколько облаков.
* **Переднее небо** (`.sky--front`, `z-index: 5`) — 4 облака **поверх
  содержимого**. Зафиксированы при скролле (`position: fixed`, без
  трансформаций) и накрывают изображения. Два ограничения, без которых слой
  мешал: он появляется только за первым экраном (иначе фиксированное облако
  ложится на портрет и на имя) и работает на половинной плотности — слой
  проходит и над подписями кейсов, а не только над кадрами. На экранах
  до 1024 px передний слой скрыт совсем.

Позиции, размер, наклон и плотность — в `styles.css`, раздел
`03. НЕБО И ОБЛАКА`. Наклон задан свойством `rotate`, а не `transform`:
`transform` занят параллаксом, и они спокойно складываются.

Лицензионных ограничений нет: рисунки сделаны с нуля.

### Движение на стоящей странице

Раньше облака двигались только от скролла — на открытой, но нелистаемой
вкладке небо стояло мёртвой картинкой. Теперь у каждого облака есть
собственное «дыхание»: `float-a` / `float-b` для заднего слоя и `float-soft`
для переднего.

Три вещи, на которых это держится:

* **`alternate`.** Облако качается туда-обратно, а не пробегает путь и не
  прыгает в начало. Прежняя анимация `drift` была `linear infinite` без
  `alternate` — на стыке цикла она давала скачок, просто период был такой
  длинный (170–290 с), что до скачка мало кто досиживал.
* **Взаимно непростые периоды и отрицательные задержки** (`23s -4s`,
  `31s -12s`, …). Иначе слои сходятся в общий такт, и небо начинает «дышать»
  синхронно — это сразу видно и выглядит механически.
* **Горизонталь в процентах, вертикаль в пикселях.** Проценты считаются от
  ширины самого облака, поэтому крупные идут заметнее мелких — как в настоящем
  небе. Вертикаль одинаковая для всех: в процентах большие облака начинали
  «нырять».

Размах — примерно ±3% ширины облака и ±7px по вертикали, период 19–39 секунд.
Всего облаков 22: 18 в заднем небе и 4 в переднем слое. Второй ряд задних
(`.cloud--15…22`) садится в промежутки между первым и взят мельче — крупные
облака вторым слоем читались бы как дубли. На телефоне из всех показываются
шесть: остальные скрыты через `@media (max-width: 760px)`, иначе небо забивает
собой содержимое на узком экране.
Хотите заметнее — увеличьте проценты в `@keyframes float-a` и `float-b`;
спокойнее — увеличьте длительности. При `prefers-reduced-motion` анимация
выключается целиком.

## Анимация и доступность

* **Параллакс облаков** считается не «по скорости», а по нормализованному прогрессу
  страницы: каждый слой проходит заданный путь в `vh` от начала до конца скролла,
  поэтому облака остаются в кадре, а не улетают на первом экране.
* **В секции работ** небо автоматически приглушается до 32% прозрачности —
  фотографии важнее фона.
* **Восемь слоёв облаков** распределены по всей длине лендинга: у каждого своя
  стартовая высота и длина пути (`data-start` / `data-travel` в разметке, в `vh`),
  поэтому в кадре почти всегда три слоя на разной глубине. Чтобы переставить
  слой — правьте атрибуты в `index.html`, скрипт трогать не нужно.
* **На мобильных** остаются два неподвижных слоя, сложный параллакс отключён.
* **`prefers-reduced-motion`** обработан: облака неподвижны, бегущая строка
  останавливается, reveal-анимации выключены, контент показывается сразу.
* Reveal-анимации применяются только при включённом JS (класс `.js` на `<html>`) —
  с отключённым JavaScript весь текст и все изображения остаются видимыми.
* Модальное окно кейса: закрытие по `Escape`, по клику на подложку и по кнопке,
  фокус удерживается внутри окна и возвращается на кнопку, с которой его открыли.
* Везде видимый `:focus-visible`, семантические теги, `alt` у всех смысловых
  изображений, ссылка «Перейти к работам» для клавиатуры.

Проверено на ширинах 375, 768, 1024 и 1440 px.

## Технические заметки

* Внешних зависимостей нет. GSAP не подключался — вся анимация уместилась
  в CSS-переходы и один `requestAnimationFrame`-обработчик скролла.
* Единственный внешний ресурс — шрифт Google Fonts. **Golos Text**, одно
  семейство на весь сайт (400/500/600/700/900). Иерархия строится весом и
  масштабом, а не набором разных гарнитур — до этого их было три и они
  конфликтовали. Golos Text выбран потому, что: у его тяжёлого начертания
  та же плотная уверенность, что у гротеска на ваших обложках; кириллица
  нарисована родной, а не выведена из латиницы; диапазон 400–900 закрывает
  всю иерархию одним файлом. Токен один — `--font`.
* Облака — векторные SVG (~1,2 КБ каждое): 32 КБ на все шестнадцать
  экземпляров, и они не размываются ни на каком экране.
* Изображения работ пережаты до разумных размеров (прогрессивный JPEG, ~1200–1900 px).
  Оригиналы остались нетронутыми в `assets/img/` и `assets/raw/`.

### Курсор

Вместо системной стрелки — маленькое облако того же рисунка, что и в небе;
на всём кликабельном оно сменяется плотным кружком чернильного цвета.
Оба курсора — SVG в `data:`-URI прямо в `styles.css`, без единой строки JS.

Почему без JS: скриптовый курсор приходится гнать за мышью каждый кадр,
и на слабой машине он заметно отстаёт от настоящего указателя — получается
два указателя вместо одного. У курсора через CSS отставания нет по определению.

Две вещи, которые важно не сломать при правках:

* **Точка в левом верхнем углу облака.** Облако большое и мягкое, по нему
  непонятно, куда именно вы целитесь. Точка стоит ровно в горячей точке
  (координаты `5 5` в конце значения `cursor`) и возвращает точность попадания.
  Сдвинете рисунок — сдвиньте и эти два числа.
* **Размер 28px.** Chrome под Windows игнорирует курсоры крупнее 32px
  и молча возвращает системную стрелку.

Хвост `, auto` и `, pointer` в значении — запасной вариант на случай,
если браузер не возьмёт картинку.

### Рисованные значки

Стрелки, звёздочки, спираль, галочка, зигзаг и крестик — двенадцать штук по
всей странице, белые и синие. Живут спрайтом в самом начале `<body>`: один
набор `<symbol>`, дальше на странице стоят ссылки вида

```html
<svg class="doodle doodle--hero-1" aria-hidden="true"><use href="#d-star"/></svg>
```

Три решения, из-за которых это устроено именно так:

* **Дрожание руки запечено в координаты путей, а не сделано фильтром.**
  У облаков неровность рисует `feTurbulence` — но облака лежат в `<img>`
  и растрируются браузером один раз. Значки же встроены в страницу, и живой
  фильтр на каждом из двенадцати пересчитывался бы при каждой перерисовке.
  Здесь вместо фильтра гладкий шум, добавленный к точкам при генерации.
* **Цвет берётся из `currentColor`.** Поэтому один спрайт даёт и белые значки,
  и синие — файлов не двенадцать и не двадцать четыре, а один. Синим задана
  меньшая непрозрачность: на небе синий тяжелее белого и при равной плотности
  начинает спорить с текстом.
* **Позиции подобраны перебором, а не на глаз.** В браузере прогнан поиск по
  сетке с проверкой пересечений — причём со строками текста через `Range`,
  а не с боксами блочных элементов: заголовок `h2` занимает всю ширину колонки,
  хотя буквы стоят слева, и по боксам «свободных мест» не находилось вовсе.
  Два значка после этой проверки переехали.

`pointer-events: none` — значок не перехватывает клик и не меняет курсор;
`aria-hidden` — для скринридера их нет, это чистый декор; `overflow: visible` —
без него дрожание срезается по краю viewBox.

Показываются не везде: до 1100px прячутся четыре значка из раздела работ и
стрелка у ленты (там сетка кейсов схлопывается в одну колонку, и боковые поля,
в которых они стояли, исчезают), а до 760px остаются всего три.

Важная деталь проверки: измерять пересечения нужно **после того, как отыграли
reveal-анимации**. Пока блоки едут снизу вверх, их прямоугольники смещены,
и проверка честно рапортует о наложениях, которых в покое нет. Первые прогоны
я поймал именно на этом — сначала прокрутите страницу до конца, дайте секунду
и только потом меряйте.

Чтобы убрать все разом — удалите блок `.doodle` в `styles.css`; разметка без
стилей ничего не рисует.

### Первый экран

**У `.hero` нет `min-height: 100svh`** — и это главное решение раздела.
Экран, растянутый на всю высоту, содержимым заполняется примерно на 530px,
и лишняя высота обязана куда-то деться. При центрировании она уходила вниз:
до «Избранных работ» получался разрыв в 209px. При прижатии содержимого книзу
она уходила наверх: под шапкой появлялся провал. Оба провала — следствие
лишней высоты, а не выравнивания, поэтому высоту и убрали: теперь она
считается по содержимому. Под шапкой остаётся 37–67px воздуха, до заголовка
работ — около 95px.

**Фото выровнено по оси имени, а не всего заголовка.** Оно позиционируется
относительно обёртки `.hero__head` (заголовок + фото), а не всей секции —
иначе оно вставало бы по центру экрана, то есть заметно ниже строки с именем.
Строку «Графический дизайнер» с её нижним отступом при этом нужно вычесть,
иначе ось уезжает вверх примерно на 20px: за это отвечает переменная
`--role-block`, повторяющая формулы из `.hero__title-role`.

На десктопе к оси добавлен небольшой опуск `--drop`: строго по центру крупный
кадр смотрелся высоковато — большое изображение визуально тянет вверх сильнее,
чем строка текста. На телефоне этот сдвиг не нужен, там фото маленькое.

**На телефоне фото тоже есть** — небольшое, справа от имени. Кегль имени там
пришлось чуть уменьшить (`clamp(2.3rem, 10.5vw, 3rem)`): при прежнем
«ЕЛИЗАВЕТА» занимало 287px из 354 доступных, и фото любого разумного размера
налезало на букву «А».

**Граница «телефонной» трактовки — 760px, а не 899.** Это важно: при 899
уменьшенный кегль и маленькое фото захватывали и планшет. На экране 768px имя
упиралось в потолок `3rem` (48px), а фото — в 108px, и первый экран выглядел
игрушечным. Сейчас с 761px и выше работает обычная раскладка: имя от 9.2vw
(70px на 768-м), фото от 27vw (207px) и зарезервированная под него полоса
справа от заголовка. Проверено на 761, 768, 800, 900, 1024 — фото нигде
не наезжает на имя.

### Пометки на тексте

Ключевые слова обведены и подчёркнуты, как будто по распечатке прошлись
карандашом: «узнаваемыми», «ясным», «заметным», «системе», «язык». Разметка —
`<span class="mark mark--circle">слово<svg><use href="#m-circle"/></svg></span>`.

Два условия, без которых это разваливается:

* **Широкий viewBox у символов** (240 единиц). Рисунок растягивается под
  конкретное слово; если сделать viewBox квадратным, овал под длинным словом
  растянется втрое и вертикальные штрихи станут втрое толще горизонтальных.
* **`white-space: nowrap` на `.mark`.** Если помеченное слово разорвётся
  переносом, рисунок останется на первой строке и повиснет в воздухе.
  Поэтому помечаем отдельные слова, а не фразы.


### Кеш при обновлении сайта

В `_headers` для `index.html`, `styles.css` и `script.js` стоит
`Cache-Control: no-cache`. Это не запрет кеша, а требование спросить сервер,
не изменился ли файл. Без него браузер кеширует по своим эвристикам и может
показывать старую версию — я сам на этом попался при проверке правок: файл на
диске уже новый, а страница упорно показывала прежние картинки в кейсе.

### Раздел работ на планшете

В медиазапросе `max-width: 1024px` лежали противоречивые правила: кейсы
`--offset` и `--right` сначала растягивались во всю ширину, а несколькими
строками ниже тем же селекторам снова назначались колонки `1 / 4` — три из
двенадцати, около 170px. Описание кейса в такой колонке разваливалось на
строки по два слова. Правила переписаны: изображение во всю ширину, подпись
под ним, ширина текста ограничена 62 символами.

Отдельно стоит запомнить причину, по которой первая попытка починки
не сработала. Правило записали коротко — `.work__media { grid-column: 1 / -1 }`.
Оно проиграло: у десктопных правил вида `.work--right .work__media`
специфичность выше, а медиазапрос специфичности не добавляет. Пришлось
перечислить модификаторы явно. Если будете править эту раскладку — селекторы
внутри медиазапроса должны быть не менее специфичными, чем базовые.

Исключение оставлено одно: `--tall` (кейс STIHL). У него вертикальная обложка,
и рядом с ней остаются честные пять колонок под текст.

### Обрезанные верхушки облаков

У девяти облаков из двенадцати рисунок выходил за `viewBox`, а корневой `<svg>`
по умолчанию обрезает всё, что за его пределами. Верхние дуги срезало ровной
горизонталью — облако выглядело подпиленным.

Причина в том, как облака генерировались: контрольные точки кривых уходили
в отрицательные Y (до −63), и по ним `viewBox` не выставлялся. Габарит нельзя
считать по контрольным точкам — кривая проходит внутри их оболочки, но всё
равно может подниматься выше нуля.

`viewBox` пересчитан по настоящему габариту: пути разбираются и плотно
сэмплируются (де Кастельжо), к результату добавляется половина толщины штриха
плюс 10px на смещение от `feDisplacementMap`. Пропорция файла при этом
меняется — сверху появляется прозрачное поле, — но сам рисунок остаётся
прежнего размера и больше не режется.

Если будете рисовать новые облака: проверяйте, что `viewBox` покрывает всю
геометрию с запасом на дрожание фильтра.

## Что сделано в предзапусковом аудите

Разделы ниже описывают правки, которые не видны глазом, но влияют на выдачу,
скорость и доступность.

### Поисковая выдача и превью ссылок

* `assets/images/og-cover.jpg` — карточка 1200×630 для превью в мессенджерах
  и соцсетях: то же небо, та же типографика, что на первом экране. Раньше
  в `og:image` стоял рекламный постер из кейса.
* `canonical`, `og:url`, `og:site_name`, `og:image:width/height/alt`,
  `twitter:card`, `author` — добавлены.
* JSON-LD (`ProfilePage` → `Person`) в конце `<head>`: имя, специальность, город,
  почта, соцсети, список компетенций. Это то, из чего поиск собирает карточку
  человека вместо обычной синей ссылки. Домен в разметке не нужен.
* `robots.txt` — сайт открыт для индексации целиком. Карты сайта нет намеренно:
  страница одна, поисковику нечего обходить.
* `<meta name="robots" content="index, follow, max-image-preview:large">` —
  без него Google показывает в выдаче миниатюру размером со спичечный коробок;
  с ним — крупное превью.

### Иконки

Собраны из вашего `my_logo.png`. Взят **только знак (лицо), без надписи
«Li3a»**: логотип горизонтальный, пропорция 3,39, и в квадрат 16×16 надпись
не помещается — на вкладке из неё получается серая полоска.

| Файл | Где виден |
|---|---|
| `favicon.ico` (16/32/48 в одном файле) | вкладка браузера, закладки, ярлык на Windows |
| `assets/images/icon-192.png` | выдача Google на телефоне, Android |
| `assets/images/icon-512.png` | заставка при добавлении на домашний экран |
| `assets/images/icon-maskable-512.png` | Android, где иконку обрезают в круг |
| `assets/images/apple-touch-icon.png` (180×180) | иконка на домашнем экране iPhone |
| `site.webmanifest` | имя «Li3a», цвета и список иконок для всего перечисленного |

Два решения, которые важно не сломать при пересборке:

* **Знак синий на бумажном фоне, а не белый на голубом.** Так голубого фона
  в иконке практически нет. Пока знак был белым на голубом квадрате, фон
  занимал больше половины площади — при любом масштабе, потому что силуэт
  головы круглый и углы квадрата всё равно оставались заливкой. Инверсия решает
  это иначе: бумажный фон на светлой панели вкладок почти растворяется, и
  визуально остаётся один синий знак.
* **Знак занимает 2/3 квадрата.** Контраст `#1B3AA8` на `#F2F0ED` — 8,3:1,
  силуэт держится и на 16px.
* **Отдельный файл для Android.** Система обрезает иконку в круг диаметром 80%
  от квадрата, поэтому у `icon-maskable-512.png` знак мельче (55%) — целиком
  внутри круга. В манифесте он помечен `"purpose": "maskable"`, обычные иконки
  лежат рядом и используются везде, где обрезки нет.
* **Палитра 32 цвета.** В иконке всего две краски плюс сглаживание — квантование
  уменьшает файлы втрое (512px: 39 → 14 КБ) и на глаз не отличается.
* **Фон `--sky-deep` (#4775E1), знак белый.** Контраст 4,3:1 — на 16px это
  минимум, при котором силуэт ещё читается. На основном небе (#5FA3F0) вышло бы
  2,9:1, и знак расплывался бы в цветное пятно.

Google показывает иконку в выдаче только если она квадратная и кратна 48px —
поэтому в наборе есть и 48 внутри `.ico`, и 192 (это 4×48) отдельным файлом.

Пути к иконкам относительные, чтобы `index.html` по-прежнему открывался
двойным кликом с диска.

### Доступность

* **Мобильное меню.** Закрытое меню уезжало за экран через `translateY(-100%)`,
  но оставалось в цепочке Tab и в дереве доступности: с клавиатуры и со
  скринридером пользователь попадал на три невидимые ссылки. Добавлен
  `visibility: hidden` с задержкой, равной анимации.
* **Площадь нажатия.** Иконки Telegram и Instagram в шапке имели кликабельную
  область 17×17, ссылка «Наверх» — высоту 14px. WCAG 2.2 требует минимум 24×24.
  Сами иконки не изменились, выросли только прозрачные поля вокруг.
* **Ссылка «Перейти к содержимому»** вела на блок работ, то есть мимо
  заголовка `h1`. Теперь ведёт на `<main id="main">`.

### Скорость

* Кадры нижней ленты были 860px шириной при отрисовке 63–258px — до 13 крат
  избыточности. Пересобраны под высоту 440px (это 2,4 высоты отрисовки, запас
  на retina): **1754 КБ → 776 КБ**. Атрибуты `width`/`height` в разметке
  обновлены, поэтому вёрстка по-прежнему не дёргается при загрузке.
* Логотипы клиентов приведены к трёхкратной ширине отрисовки: 212 КБ → 144 КБ.
  Два файла после пересжатия становились тяжелее — для них оставлены оригиналы.
* `fetchpriority="high"` стоял на обложке первого кейса, то есть ниже сгиба.
  Перенесён на портрет в первом экране — именно он определяет LCP.
* Облака первого экрана больше не `loading="lazy"`.
* Обложки кейсов не трогали: они уже сжаты плотно, перекодировка давала −1%
  при потере качества.

Суммарно страница со всеми изображениями: **3,4 МБ → 2,7 МБ**.

### Мелочи, которые чинились попутно

* `font-weight: 800` у имени в первом экране: из Google Fonts приходят
  400/500/600/700/900, и браузер молча подставлял 900. В стилях теперь написано
  то, что реально рисуется.
* Класс `js` переехал из `script.js` прямо в `<html>`: раньше между отрисовкой
  стилей и загрузкой скрипта успевало мигнуть неанимированное содержимое.
  Для выключенного JS добавлен `<noscript>` со стилем-страховкой.
* Иконка сайта использовала цвет из старой палитры (`#102A43`).
* Убраны служебные файлы `.DS_Store` и пустые атрибуты `class=""`.
* Комментарий в `<head>` обещал шрифты Onest и Inter, хотя грузится Golos Text;
  оглавление в начале `styles.css` ссылалось на удалённые разделы.

### Заголовки безопасности (`_headers`)

К прежним `nosniff`, `Referrer-Policy` и `X-Frame-Options` добавлены:

| Заголовок | Зачем |
|---|---|
| `Strict-Transport-Security` | браузер запоминает, что сюда только по https |
| `Cross-Origin-Opener-Policy` | чужая вкладка не получит доступ к окну сайта |
| `Permissions-Policy` | камера, микрофон, геопозиция и оплата закрыты — сайту они не нужны |
| `Content-Security-Policy` | разрешены только свои файлы и шрифты Google |

CSP содержит хеш блока JSON-LD. Если будете править его текст, хеш перестанет
совпадать — в консоли появится предупреждение, на вид сайта это не влияет.
Пересчитать так (из папки проекта):

```bash
python3 -c "import re,hashlib,base64,io;s=io.open('index.html',encoding='utf-8').read();m=re.search(r'<script type=\"application/ld\+json\">(.*?)</script>',s,re.S);print('sha256-'+base64.b64encode(hashlib.sha256(m.group(1).encode()).digest()).decode())"
```
